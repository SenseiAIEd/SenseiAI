## How to print or hand-copy

**Option A — print:** print `ques.png` + `bad_1.png` + `good_1.png` at 100%, portrait, no shrink-to-fit if digits stay large. One sheet each.

**Option B — hand-copy (preferred for live rewrite):** write problem once at top; keep a separate **bad_1** sheet for Check #1 and a clean **good_1** control sheet. Use thick dark marker / pen. Digits ≥ ~1 cm tall.

Live Fri run uses the **bad_1** energy under camera, then student rewrites the fix in place (large dark ink). Keep `good_1` for control only.

## Exact problem text

```
A ball is launched at 20 m/s, 60° above the horizontal.
How long until it returns to launch height? (g = 9.8 m/s²)
```

Correct path (do **not** put on the planted sheet):  
`v_y = 20 sin(60) ≈ 17.32 m/s` → `t_up ≈ 1.77 s` → `t_total ≈ 3.54 s`

## Planted work block (bad_1 — under camera at Check #1)

```
v_y = 20 m/s
t_up = v_y / g = 20 / 9.8 = 2.04 s
t_total = 2 x 2.04 = 4.08 s
```

**First error = line 1** — used full speed as vertical component (never resolved the vector).  
Lines 2–3 are correct *method* on the wrong number. That is the teaching point.

## Fix block (student rewrites after Hint, before Check #2)

```
v_y = 20 sin(60) = 17.32 m/s
t_up = 17.32 / 9.8 = 1.77 s
t_total = 2 x 1.77 = 3.54 s
```

## Control sheet (good_1)

Same problem, correct components from the start. Zero false alarms expected. Do not plant this under camera for the live story — control-only.

## Capture hygiene (Scout)

- **Square-on** — camera perpendicular to paper; no tilt
- **Even light** — kill glare / shadows; desk lamp off-axis if needed
- **Big dark digits** — thick marker; avoid faint pencil
- Tight crop of work area; pause 2 s after slide before Check
- Re-center if OCR slips; same angle Thu rehearsal = Fri live
